**RDBMS (Relational Database Management System)**
==🟢***1. Introduction***==

- RDBMS concepts were introduced by E. F. Codd (Edgar Frank Codd).
    
- E. F. Codd introduced 12 rules called Codd's Rules.
    
- A DBMS that follows all Codd's rules is called a perfect RDBMS.
    
- In RDBMS, data is organized in tables, i.e., rows and columns.
    

==🟢***2. Table Structure***==

*`Example:` CUSTOMER*

| customerId | customerName | city      |
| ---------- | ------------ | --------- |
| 100        | Vijay        | Hyderabad |
| 101        | Rahul        | Bengluru  |
| 102        | Sachin       | Mumbai    |

- Columns: Fields / Attributes
    
- Row: Record / Tuple
    

***Database Structure***

- Database: Collection of tables
    
- Table: Collection of rows and columns
    
- Row: Collection of field values
    
- Column: Collection of values for one field
    

==🟢***3. Primary Key and Foreign Key***==

*Primary Key (PK)*

- Every table should have a primary key to uniquely identify records.

`Examples:` empid, accno, aadharno, panno, voterid.

*Foreign Key (FK)*

- A foreign key is used to relate one table to another.
    
- To establish a relationship, take the primary key of one table and add it to another table as a foreign key.
    

`Example:`

PROJECTS

|projid (PK)|name|duration|cost|client|
|---|---|---|---|---|
|1000|KKK|5|400|DBS Bank|
|1001|BBB|3|200|Airlines|

EMP

|empid (PK)|ename|job|sal|projid (FK)|
|---|---|---|---|---|
|100|A|SE|35K|1000|
|101|B|SSE|90K|1001|
|102|C|TL|120K|1000|

Here, `projid` in the EMP table refers to `projid` in the PROJECTS table.

==🟢***4. RDBMS Features***==

*1. Easy to Access and Manipulate Data*

- Instead of writing complex programs, we can work with databases by writing simple queries.

*2. Less Redundancy*

- Data can be stored in multiple related tables using foreign keys, which helps reduce redundancy.

*3. Supports Security*

- Only authorized users can access the database.

*4. Guarantees Data Quality*

- RDBMS supports integrity constraints to maintain correct and valid data.

*5. Supports Data Sharing*

- Multiple users can connect to the database and access the same data at the same time.

*6. Supports Transactions*

- RDBMS supports transaction properties called ACID properties.

- A – Atomicity
    
- C – Consistency
    
- I – Isolation
    
- D – Durability

==🟠***ORDBMS (Object-Relational Database Management System)***==

*1. Introduction*

- ORDBMS stands for Object-Relational Database Management System.
    
- It is a combination of RDBMS and OOP concepts.
    

`[ ORDBMS = RDBMS + OOP Concepts ]`

- ORDBMS supports object-oriented features like reusability and complex data types.

*2. RDBMS vs. ORDBMS*

*RDBMS Example*

CUST

|cid|name|hno|street|city|state|pin|
|---|---|---|---|---|---|---|

EMP

|empid|ename|hno|street|city|state|pin|
|---|---|---|---|---|---|---|

*==🟡Here, address details are repeated in both tables.==*

### ORDBMS Example

ADDR

|hno|street|city|state|pin|
|---|---|---|---|---|

CUST

|cid|cname|addr|
|---|---|---|

EMP

|empid|ename|addr|
|---|---|---|

*==🟡Here, address details are grouped into a reusable structure and used by both tables.==*
